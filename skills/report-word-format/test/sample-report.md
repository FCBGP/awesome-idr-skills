# 三、关键技术调研情况

## 3.1 路由安全技术调研

### 3.1.1 RPKI及路由起源验证技术现状

#### 3.1.1.1 RPKI/ROA/ROV基本机制

**（1）研究现状**

RPKI通过资源证书、路由源授权和验证器构建路由起源验证体系，用于判断某一自治系统是否被授权宣告特定 IP 前缀。ROA记录前缀、最大长度和授权 AS 号，ROV则在路由器或控制系统中根据验证结果对路由进行接受、降级或过滤处理[1]。

**（2）主要局限**

当前RPKI部署仍面临覆盖率不均衡、运营策略差异较大、错误ROA可能影响正常路由可达性等问题。对于跨区域、多运营主体和多源数据融合场景，仅依赖单一验证结果难以形成完整的可信路由视图。

#### 3.1.1.2 公开路由测量数据源

公开路由测量数据可为路由状态感知、异常检测和历史回溯提供基础。RouteViews 和 RIPE RIS 长期采集全球多个观测点的 BGP RIB 与 UPDATE 数据，BGPStream 则提供统一的数据访问和处理接口[2]。

### 3.1.2 开源工具链调研

#### 3.1.2.1 验证器与路由软件

**（1）Routinator**

Routinator 是 NLnet Labs 维护的 RPKI 验证器，可从信任锚定位器获取资源证书链与ROA数据，并对外提供 RTR、HTTP 和 JSON 等接口，适合与路由器、监测平台或离线分析脚本集成[3]。

**（2）FRRouting**

FRRouting 是常用的开源路由协议栈，支持 BGP、OSPF、IS-IS 等协议，可用于构建实验网络、验证路由策略和测试 RPKI-RTR 接入效果[4]。

## 3.2 多源共识一致性验证技术调研

### 3.2.1 多源数据融合与一致性判断

#### 3.2.1.1 多源视图构建方法

多源共识一致性验证通常需要将路由采集器、RPKI验证器、运营商策略库和安全事件情报进行统一建模。常见流程包括数据接入、字段归一、时间对齐、冲突检测和可信视图生成。

1）多源数据接入与模板化治理。系统需要为BGP更新、ROA快照、告警事件和人工策略配置建立统一字段模板，降低不同来源之间的语义差异。

2）分组共识与可信视图生成。系统可根据观测点区域、数据源可信度和时间窗口对结果分组，再通过多数一致、权重投票或规则优先级生成候选视图。

3）异常回溯与解释。对于不一致结果，需要保留原始证据链和中间判断过程，以便支撑告警解释、人工复核和策略调整。

#### 3.2.1.2 代表性问题与风险

多源一致性分析面临观测点偏差、采样频率不一致、数据延迟、格式变化和局部策略不可见等问题。若缺少时间窗口约束和证据链管理，系统可能将正常的传播延迟误判为异常，也可能因单一观测点异常导致全局判断偏差。

# 四、结论与建议

## 4.1 调研结论

RPKI、ROV、公开BGP测量数据和开源路由工具链已经为路由安全分析提供了较成熟的基础能力，但在跨源数据一致性、证据链保留、自动化解释和运营策略融合方面仍存在改进空间。

## 4.2 后续建议

后续平台可优先建设统一数据模型、可复现实验管线和面向运营场景的异常解释机制。在工程实现上，应保持数据采集、验证计算、规则配置和结果展示之间的松耦合，以便适配不同网络环境和数据源更新。
